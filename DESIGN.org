#+title: emms-lyrics-sync — design notes
#+author: lxg208
#+options: toc:t num:nil

Notes on architecture, key decisions, and display-engine quirks.  Aimed
at contributors and at future maintainers (including future-you).

* Three-window architecture

The display is a sidebar of three stacked side windows, grouped
atomically:

#+begin_example
  ┌──────────────────────────┐
  │  *emms-lyrics-metadata*  │  slot 0, fixed height
  │  cover + header          │
  ├──────────────────────────┤
  │  *emms-lyrics*           │  slot 1, flexible height
  │  lyrics (scrollable)     │
  ├──────────────────────────┤
  │  *emms-lyrics-waveform*  │  slot 2, fixed height
  │  waveform + mode line    │
  └──────────────────────────┘
#+end_example

Grouping is done via =window-make-atom= on the common parent.
=delete-window= on any constituent deletes the whole group; =q= is
bound to =emms-lyrics-sync-display-hide= in each mode's keymap, which
calls =(delete-window (window-atom-root (selected-window)))=.

** Why three windows instead of one

The waveform's Y position must be stable.  With a single buffer
containing cover + header + lyrics + waveform, the waveform drifts
vertically as lyric lines of different heights scroll past above it.
This produced 1–3 px line-height "jitter" that was impossible to
eliminate because the display engine gave no reliable control over
per-line height:

- The =line-height= text property (documented in the Emacs Lisp
  manual, added in Emacs 29) is silently ignored on Emacs 31.1 and
  32.0.50.  Isolated test: a two-line buffer with distinct
  =line-height= properties renders both lines identically.
- The =(space :width 0 :height H)= display spec is also ignored.
- =(space :width 1 :height H)= produces line heights roughly 2× the
  target and applies inconsistently.
- =(height H)= on a hair space works for line height but leaves the
  carrier character visible under =hl-line=.

Splitting the waveform into its own fixed-height window eliminates
jitter by construction.  The waveform cannot move.  Once this landed,
=display-cjk-scale= became a pure aesthetic choice — the previous
empirical ceiling (per-machine, ~1.10–1.15) no longer applies.

* CJK / Latin font split

Emacs needs different fonts and heights for Latin and CJK within the
same buffer.  Options considered:

1. *Fontsets.*  =create-fontset-from-fontset-spec= +
   =set-fontset-font=.  Broken on Emacs 31/32: the fontset name is
   registered but the object cannot be modified
   (=set-fontset-font= returns nil, =fontset-font= returns only
   fallback bitmaps, =internal-delete-fontset= errors).

2. *Frame-level fontset override.*  =(set-fontset-font t 'han …)=
   overrides CJK in *every* buffer on the frame.  Works but leaks:
   changing =display-font-family= to Sarasa, NSimSun, etc. has no
   effect on CJK because the frame-level mapping wins.

3. *Face text properties* (chosen).  Walk the buffer after each
   render; for each CJK run, add a face text property with the
   desired family and height.  Face text properties honor both
   =:family= and =:height=, are buffer-local, and coexist with
   existing face attributes (colors, A2 word underlines) via
   =add-face-text-property= with ='append=.

CJK detection uses =(= 2 (char-width c))= — East Asian Width returns 2
for kanji, kana, hangul, bopomofo, fullwidth forms, and CJK
punctuation.  =get-char-code-property= with 'script does not work
(script data lives in Scripts.txt, not UnicodeData.txt, and is not
exposed through that function).

** x-height calibration

=emms-lyrics-sync-display-calibrate-cjk-scale= measures the actual
x-heights of the resolved font files via =freetype-py= at 400 px with
=FT_LOAD_NO_HINTING= (small sizes give noisy results due to freetype
hinting rounding).  The computed ratio is the *mathematical* x-height
match; users typically multiply by 1.05–1.15 for perceptual balance
(CJK glyphs have lower stroke density per unit area, so they read
smaller at x-height parity).

Font path → file mapping uses =font-info=, which returns a 12-element
vector with the file path at index 11.  Paths must be decoded from
unibyte with =file-name-coding-system= before use in =message= or
process arguments.

* Waveform generation

The waveform is generated by =ffmpeg= as two full-width PNGs (played
and remaining), then composited per tick by:

1. Crop the played image to =[0, cursor-x]=
2. Crop the remaining image to =[cursor-x, end]=
3. =hstack= the two crops into a single composite PNG
4. Display the composite in the waveform buffer

The composite step uses =call-process ffmpeg= once per second
(throttled via =--tick-counter=).  Attempts to replace this with
pure-Elisp =image-crop= failed: Emacs 32's =image-crop= is a
different-arity interactive command, and =:crop= / =:slice= display
properties on inline images render at full size.  The per-second
ffmpeg call is ~20–50 ms on the fast build, well below the 100 ms
tick budget.

** Filter pipeline

The =showwavespic= filter is invoked with =split_channels=0= at full
px-h, then cropped to the top half for L and bottom half for R, then
=vstack= to produce the foobar2000-style dual-channel layout with a
shared center line.

A 1-px =drawbox= line is drawn at the center of each half before
overlay, so silent regions render as a flat colored line at center
(the standard "silence" appearance in Audacity and foobar2000).
Without this, silence renders as transparent and looks like blank
space.

Scale is =linear= (the default).  =sqrt= scale was tried and reverted
— over-compressed albums (the "loudness war" case) render as a solid
rectangle either way, and linear is a more accurate representation of
what's actually in the file.

** Composite ffmpeg filter

#+begin_example
  [0:v]crop=cursor-x:px-h:0:0,format=rgb24[left];
  [1:v]crop=remaining-w:px-h:cursor-x:0,format=rgb24[right];
  [left][right]hstack=inputs=2,format=rgb24
#+end_example

=format=rgb24= after each crop is required.  Without it, filter
negotiation falls through to YUV 4:2:0 which requires even dimensions
and silently truncates.

** Async generation

=showwavespic= on a 5-minute track takes 5–30 s (decode time, not
build speed).  PNG generation runs via =make-process= with a sentinel;
the Unicode flat bar renders as a placeholder during the wait and is
replaced by the composite PNG when the sentinel fires.

* Seeking

*** Keyboard

=RET= on a lyric line seeks to the line's =start-ms= (stored as a
text property during render).  Works for both synced LRC and A2
(word-level) lines.

*** Mouse

=mouse-1= on the waveform seeks to the corresponding X position.  X
is computed as =click-x − side-padding × char-width=, which is
deterministic — no reliance on =posn-at-point= of the image, which
returns inconsistent results for inline images.

*** Stopped case

When the player is stopped, both handlers queue the seek in
=emms-lyrics-sync-core--pending-seek= (a =CONS= of =(file . sec)=)
and call =emms-start=.  =--mpv-connect= applies the pending seek when
the socket becomes reachable.  On WSL this is important: mpv takes
2–3 s to buffer from the network drive, and seeks before buffering
completes are silently discarded.

*** Paused case

Both handlers call =emms-pause= after seeking if
=emms-player-paused-p= is non-nil, so playback resumes from the new
position.

*** Track positioning

Selecting the correct track in the playlist after adding files
required discovering that =emms-playlist-current-selected-track= is
*not* positional — in this build it's a C-level subr that returns the
persistent "selected" track (set by the last play), not the track at
point.  The correct positional accessor is
=emms-playlist-track-at (point)=.  Before calling =play-smart=, the
selection must be synced via =emms-playlist-select (point)=.

* Source pipeline

Sources are tried sequentially; the first success stops the pipeline.
Each source is an async function =(track callback)=; failures call
=callback= with =nil= to advance to the next source.

Race protection: =--on-track-change= increments
=--fetch-token=; source callbacks compare their captured token against
the current value and discard stale results.

Ordering rationale:
- =local-lrc= first: file read, no external process, instant
- =tag= second: ffprobe, ~100 ms on the fast build
- =lrclib= third: free, synced, no key
- =qqmusic= fourth: per-phrase timestamps (better for karaoke)
- =netease= fifth: broad CJK catalog
- =lyricsovh= last: plain text, fallback only

* mpv IPC

Position polling: =get_property time-pos= every 100 ms, response
handled in =--mpv-filter=.  Position is cached between ticks, so the
display sees a value that is at most one tick old.

Both native mpv (via =--input-ipc-server=) and WSL Windows mpv (via
=socat= bridging the Unix socket to a Windows named pipe) work
transparently because the JSON IPC protocol is identical.

** socat teardown race
Stop tears down socat before mpv closes the pipe; the 1-s
run-with-timer in --on-stop is load-bearing.  Start now waits
up to 4 s for the old process to fully exit before launching a
new one, and aborts + kills the orphan mpv if socat still fails.

* Emacs display-engine quirks encountered

Documented here so the next contributor doesn't re-discover them:

| Feature                                | Status on 31.1 / 32.0.50     |
|----------------------------------------+------------------------------|
| =line-height= text property            | Silently ignored             |
| =(space :width 0 :height H)= spec      | Silently ignored             |
| =(space :width 1 :height H)= spec      | ~2× target, inconsistent     |
| =(height H)= on hair space             | Works, but carrier visible   |
| =image-crop=                           | Replaced with different-arity interactive command |
| =:crop= / =:slice= on inline images    | Render at full size          |
| =create-fontset-from-fontset-spec=     | Produces unusable fontset    |
| =set-fontset-font t 'han …=            | Works, but frame-global      |
| =pixel-scroll-precision-mode=          | Intercepts wheel events globally |
| =emms-playlist-current-selected-track= | Persistent selection, not positional |

Workarounds in the package:
- Three-window layout instead of per-line height control
- Face text properties instead of fontsets
- Explicit =set-window-vscroll= 0 + =pixel-scroll-precision-mode -1= in
  fixed-content buffers
- =emms-playlist-track-at= + =emms-playlist-select= instead of
  =current-selected-track=

* Testing checklist

Before shipping a change to the display layer, verify on all three
machines (or at least one WSL and one native Linux):

- [ ] Play a track cold → lyrics + waveform appear
- [ ] Change track → all three windows update, no stale state
- [ ] =RET= on a lyric line → seeks correctly
- [ ] Click waveform → seeks correctly
- [ ] Pause → display freezes at current position
- [ ] Stop → waveform resets to 0:00, mode line shows 0:00
- [ ] =q= hides all three windows; =F3 L t= restores
- [ ] CJK track → CJK renders in the configured family at the
      configured scale, no jitter at any =cjk-scale= value
- [ ] A2 LRC → word-level highlighting works on current line
- [ ] Track with no cover → placeholder SVG appears
- [ ] Track with no lyrics → "(no lyrics)" in lyrics window,
      waveform still generated
